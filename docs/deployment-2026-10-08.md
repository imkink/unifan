# StampS3 首次 USB 部署记录

部署日期：2026-10-08（Asia/Shanghai）。

## 设备与固件

- 串口：`/dev/cu.usbmodem201201`。
- 芯片：ESP32-S3 QFN56，revision v0.2，内置 8MB GD Flash。
- 设备 MAC：`48:ca:43:b5:fc:00`（用于识别本次备份对应的设备）。
- 官方 MicroPython：v1.29.0，构建名 `ESP32_GENERIC_S3`，2026-08-24。
- 下载地址：<https://micropython.org/resources/firmware/ESP32_GENERIC_S3-20260824-v1.29.0.bin>。
- 下载文件 SHA-256：`1dd9dcd27ba2d6a1cb7f7b49a063f46d3d807d68b0151161233920228285e300`。
- 固件从地址 0 写入，烧录时指定实际 Flash 容量 8MB；工具修改了相应镜像头并重新计算摘要。
- esptool 写后哈希校验通过；实机确认 `network.LAN`、`PHY_W5500`、`hostname`、`ssl.SSLContext` 可用。

初始程序未响应 MicroPython 控制台。新固件写入后，普通 USB RTS 复位仍停在
`DOWNLOAD(USB/UART0)`，使用 esptool 的 `--after watchdog-reset` 后正常进入 MicroPython。
这是本次观察到的复位模式问题；不要因为控制台暂时无响应就重复擦除设备。

## 项目部署与实机结果

`tools/usb_install.py` 上传并逐个验证了 14 个文件：启动器、OTA 运行库、A 目录业务、
W5500 配置和 GitHub 根证书。`main.py` 最后上传，全部校验成功后才复位。

| 项目 | 实测结果 |
| --- | --- |
| 文件系统 | 6,291,456 字节（6 MiB），1536 个 4096 字节块 |
| W5500 DHCP 地址 | 192.168.1.223 |
| 子网掩码 | 255.255.255.0 |
| 网关 / DNS | 192.168.1.1 / 192.168.1.1 |
| GitHub HTTPS | 严格校验证书成功，分块接收仓库页面 235,861 字节 |
| Wi-Fi STA / AP | 均为关闭 |
| OTA 已确认版本 | A 目录，0.0.0，pending=-1，attempts=0 |
| 运行时检查 | uptime=138736ms，reset_cause=2（非 WDT_RESET=3） |
| 启动稳定性 | 被动观察 38 秒无异常输出；运行时检查显示已超过两分钟，无看门狗重启 |
| 运行时检查的空闲堆 | 148272 字节（中断应用读取状态并 gc.collect 后） |

独立网络诊断时，初始化 W5500 后空闲堆约 152736 字节；HTTPS 完成并回收后约 111872 字节。
这些是采样值，不是 TLS 峰值占用，也不代表后续增加网页、传感器和历史查询后仍有相同余量。

发现 `mpremote rtc --set` 默认采用电脑本地时间，本机为上海时区，会导致设备 UTC 偏差 8 小时。
已由安装工具使用 `datetime.now(timezone.utc)` 修正；读取时设备 UTC 为
`2026-10-07 16:33:34`（上海时间 `2026-10-08 00:33:34`）。

最后一次状态检查后已执行设备复位，恢复正常自动启动。
