# 电路板就绪前的业务骨架

目前可以继续做页面和数据流程，不需要先接上真实温湿度传感器和风扇。
W5500 仍使用真实网络；温湿度/PWM/转速采用明确标记的内存模拟实现。

## 文件与边界

| 文件 | 当前职责 | 电路板完成后 |
| --- | --- | --- |
| `app_config.py` | 模拟模式、初值、采样间隔，参数逐项中文说明 | 用户长期设置另存 NVS |
| `hardware.py` | 可运行的模拟传感器和六风扇/两组 PWM 接口 | 实现 ENV-III I2C、PWM 和测速占位类 |
| `control.py` | 温度曲线、迟滞、故障保护的中文伪代码 | 确认目标单位和策略后实现 |
| `telemetry.py` | 周期采样、原子替换内存快照、过期检测 | 保持接口，换成真实读取 |
| `app.py` | 启动服务、确认软件自检、监督采样并喂狗 | 增加真实硬件自检和控制任务监督 |

模拟模块完全不初始化传感器 I2C、风扇 PWM 或测速 GPIO。默认温度 26℃、湿度 55%，
两组模拟 PWM 均为 30%，演示 RPM 按占空比线性生成。它们都不是设备测量结果，
也不是已确定的风扇控制算法。`control.compute_group_targets()` 当前会明确抛出
`NotImplementedError`，不会偷偷使用临时控制策略。

把 `HARDWARE_MODE` 改成 `hardware` 不会自动得到真实驱动：占位实现会明确报错，
不会回退到模拟数据。真实模式实现后才能切换该配置。

## 后续服务如何使用

在业务启动后通过 `app.telemetry.snapshot()` 获取一份独立的可序列化快照。
包含环境数据、六个风扇及其 PWM 分组、采样序号、过期标记，以及：

```json
{
  "source": "simulated",
  "simulated": true,
  "hardware_ready": false,
  "control_policy_ready": false
}
```

页面必须明显显示“模拟数据 / 硬件未接入”；不能因为采样服务健康就显示“真实风扇正常”。
后续若保存模拟历史，应使用独立文件/命名空间，或者暂不落盘，避免混入真实七天记录。
当前只维护内存快照，不保存历史、不自动生成时间戳，也没有新增 HTTP 路由。

测试可调用 `sensor.set_environment(温度, 湿度)` 改变模拟环境，调用
`fans.set_group_pwm(组号, 百分比)` 演示分组变化。组 1 对应风扇 1～4，组 2 对应风扇 5～6。
模拟允许 0～100% 以便后续演示停转；真实需求中的最低转速限制尚未实现。

## 自检含义与后续替换

启动先完成模拟接口初始化和首次采样，再确认 OTA 启动成功；这只证明软件链路可运行。
之后检查后台任务未退出且采样未过期才喂狗，断网不影响此过程。

真实电路就绪后依次补齐：器件身份与通信校验、PWM 极性/频率、六路脉冲计数和每转脉冲数、
温度曲线目标单位、最低转速/迟滞、传感器失效与风扇失速处理。先在硬件测试中验证安全输出，
再切换真实模式，并保持网页/历史接口的模拟来源标记正确。

本次变更只更新项目源码，尚未替换 2026-10-08 已烧录设备上的启动框架。
